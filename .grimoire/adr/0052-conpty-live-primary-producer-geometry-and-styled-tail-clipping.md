# ConPTY Live Primary Producer Geometry and Styled-Tail Clipping

**Status:** Completed
**Date:** 2026-10-09
**Approval:** The user approved approach A and authorized implementation. The scoped repair and verification are recorded below; this does not complete unrelated application or release acceptance.
**Supersedes (Windows ConPTY live-primary tail retention only):** [ADR 0046](./0046-trim-ordinary-trailing-spaces-during-primary-reflow.md), [ADR 0051](./0051-modern-sgr-decoration-and-blank-retention-policy.md). Their other rules and historical statuses remain unchanged.

## Context

Primary reflow previously promised retention of styled blanks, including explicitly written decorations and styled erase/fill extents. Windows ConPTY owns the geometry used by subsequent cooked-input repaint; Harbor cannot independently create more live rows from style-only tails and still interpret that repaint at the producer's coordinates.

The supplied root-cause experiment used bundled ConPTY `1.24.260710001`, narrowing from 103 to 51 columns. Overlined, underlined, and background-colored tails of 65 blanks each added one Harbor model row relative to the producer; a full-width styled erase of 103 blanks added two. The full script accumulated a three-row mismatch. With pending cmd input, the producer's CUP + ED-to-end repaint addressed earlier rows and overwrote the `END` marker and prompt. Ordinary tails matched; without pending input, no repaint bytes were emitted in the tested case, which is not proof of geometry agreement.

Local diagnostic logs and screenshots are in `target/cmd-resize-evidence/`, notably `minimized-with-input.log`, `minimized-no-input.log`, `full-script-trace.log`, and the failing `prompt-regression.log`. These ignored artifacts support the diagnosis, not a post-fix acceptance claim. The diagnostic test reporting `ok` means the probe ran; it does not mean producer/model coordinates matched.

## Decision

- For **Windows ConPTY primary-screen resize, only the producer-owned live region**, prioritize agreement with producer text/cursor geometry. A style-only trailing blank suffix must not independently create additional physical rows.
- Preserve the suffix's cell attributes within available target-row capacity, including underline/overline and background styling and existing styled erase/fill results. Clip/discard overflowing style-only tail capacity. Do not promise that discarded blanks return on widening or survive for copy/selection; no hidden off-grid payload is required.
- Preserve actual text, significant interior spaces, explicit hard blank-line boundaries, wide-cell invariants, and producer-compatible live/saved cursor and pending-wrap semantics. Conceal is still presentation, not permission to classify hidden source text as a disposable style-only tail. The exception does not globally redefine protected or hyperlink-bearing content as ignorable.
- Only the final old source row has a trimmable tail. A prefix already marked soft-wrapped (`wrapForced`) is producer geometry, even when it contains ordinary or styled blanks. Live profiles confirmed that a 103-column forced prefix occupies three rows on the first shrink to 51; discarding that footprint duplicates/displaces pending input. After widening collapses it to one row, subsequent narrowing can trim the now-final suffix. This is not a promise to restore clipped decoration.
- Keep retained history and non-ConPTY primary reflow under the full existing rules of ADR 0046 / ADR 0051: ordinary-tail trimming with cursor exceptions, and retention of styled/protected/hyperlinked blanks. Split history/live-spanning lines at the policy boundary without projecting history into the producer's live coordinates; preserve the existing `PreserveLiveTop` boundary protection. A saved primary resized while alternate is active uses the same primary-region policy; alternate surfaces themselves remain rectangular.
- Maintain meaningful extents and content anchors for surviving cells. Endpoints in discarded overflow must clamp or invalidate consistently; they must not resolve to unrelated retained content or imply lossless round trips. Ordinary parsing, copy of retained content, renderer visibility, transactional PTY resize, and alternate-screen rectangular policy are otherwise unchanged.

## Alternatives

The user chose the bounded Harbor-side compatibility repair over keeping complete live-tail retention and changing the bundled ConPTY producer. The latter would require a verified patched producer or verified upstream release and matching distribution; no suitable already-fixed release has been established. Hidden tail storage or a second coordinate grid is not part of this approval. Dropping ED/CUP, shell-name heuristics, arbitrary row offsets, and resize-delay workarounds do not resolve the model/producer disagreement and are not authorized substitutes.

## Consequences

- This is an explicit, narrowly scoped information-loss exception to styled-tail retention, not an expansion of global ordinary-space trimming. Target-row styling is retained without letting style-only overflow move the input row away from producer geometry.
- Specs 0014/0018 and resize domain context must distinguish Windows ConPTY live primary from retained history, non-ConPTY primary, and rectangular alternate screens.
- Implementation and evidence follow local plan 0020 (`conpty-styled-tail-resize-compatibility`, not tracked). Regression acceptance must check the `END` marker, complete prompt and pending input, and subsequent typing/backspace/Enter, plus history/live boundaries, cursor cases, and unchanged full-retention policies. Payload survival alone is insufficient.
- Approval alone is not execution evidence. The scoped implementation and subsequent checks are recorded separately below; unrelated feature and release acceptance remain outside this repair.

- **Snapshot:** `0db427a` plus the local repair in `crates/harbor-terminal/src/primary_reflow.rs`, the new `crates/harbor-terminal/tests/conpty_styled_tail_resize.rs`, and the associated grimoire contract changes; no ConPTY bundle, parser, renderer or VT filtering change.
- **Environment:** Windows build `10.0.26300.9457`, PowerShell `5.1.26100.9444`, bundled ConPTY `1.24.260710001`; debug Harbor built with `cargo build --bin harbor`. The synthetic script prints HEAD, not the dirty-tree binary identity.
- **Model/producer results — PASS:** The 16 real cmd/ConPTY integration tests cover the original script, complete END/prompt/input, three 103 -> 51 -> 103 rounds, typing/Backspace/Enter and distinct echo responses, printed overline/underline/background tails, styled erase, interior spaces/CJK, history with height changes, already-wrapped ordinary/decorated prefixes, exact/new/old wide-cell edges, and long pending commands (1000 ASCII characters or 100 repetitions of ASCII `a` followed by CJK `U+754C`). Assertions cover both complete copy text and the cursor insertion boundary, including column-zero wrap boundaries.

Existing cursor/pending-wrap, parser, primary/alternate restoration and PTY barrier coverage also passed.
