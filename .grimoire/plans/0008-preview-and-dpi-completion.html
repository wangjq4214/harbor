Design Decisions

  • PreviewPane as a proper widget in harbor-widget. PreviewPane implements Component + AnyView in the harbor-widget crate. It is a reusable widget primitive — any Widget Runtime host that needs to display scrollable monospace text can compose it. It is NOT a general ScrollView: it hardcodes monospace text assumptions (character-boundary wrapping, cell_width-based sizing, read-only content). A general ScrollView with arbitrary child widgets remains out of scope.
  • Keyboard scrolling (arrows, PageUp/Down) at window level, not widget level. Keyboard events in the Widget Runtime route to the focused widget. When Cancel is focused (default), arrow keys would reach Cancel, not the preview. Handling them at the ConfirmationWindow level (before widget dispatch, like y/n/Escape) ensures keyboard scrolling works regardless of focus, while keeping FocusScope traversal simple (Tab/Shift+Tab only between interactive controls).
  • Wheel scrolling in PreviewPane widget, not window level. Wheel events go through hit testing — they must reach the widget under the pointer. PreviewPane handles wheel events during the widget dispatch phase, which is the natural routing path for pointer events. This also means wheel scrolling only happens when the pointer is over the preview area.
  • Shared scroll offset via Arc<AtomicUsize>. ConfirmationWindow owns the scroll offset (it handles keyboard scroll at window level and enforces bounds). PreviewPane reads it during paint and writes it during wheel events. Arc<AtomicUsize> avoids borrow conflicts: ConfirmationWindow mutates offset during event handling, PreviewPane reads it during paint pass, both operations happen at different phases of the frame so atomic ordering is relaxed.
  • Wrapping at construction time, not paint time. Wrapping depends on cell_width (from TextMetrics) and dialog width. These are fixed at construction (the dialog is non-resizable). Computing wrapped lines once in ConfirmationWindow::new avoids re-wrapping on every frame and ensures the wrapped text is available for ensure_glyphs before the first paint.
  • Cancel-first focus order. T0004 placed Paste first for default focus. T0005 reverses this: Cancel is the safer default. The button order in the Row is Cancel first, Paste second — focus_first_focusable() finds Cancel. This is a deliberate safety preference per the ticket.
  • Wrap root in FocusScope for Tab/Shift+Tab. The existing FocusScope widget handles Tab/Shift+Tab by emitting NavigateFocus commands on the EventCtx. Wrapping the confirmation widget tree in a FocusScope (non-modal) provides standard Tab/Shift+Tab traversal between Cancel, PreviewPane, and Paste without custom focus logic.
  • DPI-aware viewport via actual scale factor. The current render() hardcodes scale=1.0 in the viewport. The confirmation window must use the winit window's scale_factor() so text placement, layout, and hit testing agree with the physical surface. The scale factor is read from the window and passed through to the Runtime viewport on every render and resize.
  • Visible-line text batching via conditional queue_text_run. PreviewPane's paint_primitives only calls queue_text_run for lines in the visible range. TextRunCache dedup means identical lines produce the same TextRunId, but invisible lines never register at all — satisfying the acceptance criterion that preview rendering emits text only for visible lines.

Step 1: Add text-wrapping helper for preview text

Files: src/app/confirmation.rs

Action: Add a private function wrap_preview_text(raw_text: &str, max_chars: usize) -> Vec<String> that: (1) splits raw_text into lines, (2) applies harbor_types::safe_preview_line to each line to escape control characters, (3) wraps each escaped line at max_chars characters (simple character-index split, monospace), (4) returns the flat list of wrapped lines. Also compute max_chars from (DIALOG_WIDTH - 2 * padding) / cell_width.

use harbor_types::safe_preview_line;

const DIALOG_HORIZONTAL_PADDING: u32 = 48; // 24px each side

fn wrap_preview_text(raw_text: &str, max_chars: usize) -> Vec<String> {
    let mut wrapped = Vec::new();
    for line in raw_text.lines() {
        let escaped = safe_preview_line(line);
        if escaped.is_empty() {
            wrapped.push(String::new());
            continue;
        }
        let mut start = 0;
        while start < escaped.len() {
            let end = ((start + max_chars).min(escaped.len()));
            // Don't break mid-grapheme; since this is monospace ASCII+
            // (terminal output), char boundaries are sufficient.
            let end = find_char_boundary(&escaped, end);
            wrapped.push(escaped[start..end].to_string());
            start = end;
        }
    }
    wrapped
}
Outcome: wrap_preview_text unit tests pass for: empty input, single short line, single line exceeding max_chars (multiple wraps), lines with \r and control characters (visible escape), empty trailing lines, and multiline text. The wrapping correctly splits at character boundaries.

Step 2: Create PreviewPane widget in harbor-widget

Files: crates/harbor-widget/src/widgets/preview_pane.rs, crates/harbor-widget/src/widgets/mod.rs

Action: Define PreviewPane struct implementing Component and AnyView. Fields: wrapped_lines: Vec<String>, scroll_offset: Arc<AtomicUsize>, line_height: f32, visible_lines: usize, color: Color, children: Vec<View>. Its intrinsic_size computes width from the widest wrapped line and height from visible_lines * line_height. Its paint_primitives iterates visible_lines starting from scroll_offset, calling text_label::queue_text_run for each line, returning a Primitive::Text at the correct vertical offset per line. Its handle_event handles Pointer(PointerEvent { phase: Scroll, .. }) by adjusting the atomic scroll offset (clamped).

use std::sync::Arc;
use std::sync::atomic::{AtomicUsize, Ordering};
use crate::input::event::{PointerPhase, UiEvent};
use crate::input::event_ctx::{EventCtx, EventHandled};
use crate::layout::{BoxConstraints, Point, Rect, Size};
use crate::scene::primitive::{Color, Primitive};
use crate::text::current_metrics;
use crate::view::{AnyView, BuildCx, Component, Key as ViewKey, View};
use crate::widgets::text_label;

pub struct PreviewPane {
    wrapped_lines: Vec<String>,
    scroll_offset: Arc<AtomicUsize>,
    line_height: f32,
    visible_lines: usize,
    color: Color,
    children: Vec<View>,
}

impl PreviewPane {
    pub fn new(
        wrapped_lines: Vec<String>,
        scroll_offset: Arc<AtomicUsize>,
        line_height: f32,
        visible_lines: usize,
    ) -> Self {
        PreviewPane {
            wrapped_lines,
            scroll_offset,
            line_height,
            visible_lines,
            color: Color::WHITE,
            children: vec![],
        }
    }

    pub fn color(mut self, color: Color) -> Self {
        self.color = color;
        self
    }
}

impl Component for PreviewPane {
    fn build(&self, _cx: &mut BuildCx) -> View {
        View::new(self.clone(), self.children.clone(), None)
    }
}

impl AnyView for PreviewPane {
    fn intrinsic_size(&self, constraints: BoxConstraints) -> Size {
        let cell_width = current_metrics()
            .map(|m| m.cell_width).unwrap_or(10.0);
        let max_line_chars = self.wrapped_lines.iter()
            .map(|l| l.len()).max().unwrap_or(0);
        let width = max_line_chars as f32 * cell_width + 4.0;
        let height = self.visible_lines as f32 * self.line_height;
        constraints.constrain(Size::new(width, height))
    }

    fn paint_primitives(&self, rect: Rect) -> Vec<Primitive> {
        let offset = self.scroll_offset.load(Ordering::Relaxed);
        let end = (offset + self.visible_lines).min(self.wrapped_lines.len());
        let mut prims = Vec::with_capacity(end.saturating_sub(offset));
        for i in offset..end {
            let line = &self.wrapped_lines[i];
            let run_id = text_label::queue_text_run(line, self.color);
            let y = rect.min.y + (i - offset) as f32 * self.line_height;
            prims.push(Primitive::Text {
                run: run_id,
                origin: Point::new(rect.min.x, y),
                color: self.color,
            });
        }
        prims
    }

    fn handle_event(&self, event: &UiEvent, _ctx: &mut EventCtx, _rect: Rect) -> EventHandled {
        match event {
            UiEvent::Pointer(ptr) if ptr.phase == PointerPhase::Scroll => {
                let delta = ptr.scroll_delta.y;
                let current = self.scroll_offset.load(Ordering::Relaxed) as isize;
                let max_offset = self.wrapped_lines.len()
                    .saturating_sub(self.visible_lines) as isize;
                let new = (current - delta as isize).clamp(0, max_offset.max(0));
                self.scroll_offset.store(new as usize, Ordering::Relaxed);
                EventHandled::Handled
            }
            _ => EventHandled::Ignored,
        }
    }
}
Outcome: PreviewPane compiles as a proper harbor-widget widget, publicly exported from harbor_widget::widgets::preview_pane. Unit tests (in the crate's test module) pass: intrinsic size reflects widest line and visible-line count; paint only emits primitives for visible range; wheel down increments scroll offset (clamped to max); wheel up decrements (clamped to 0); non-scroll events are ignored.

Step 5: Add scroll event handling at window level for keyboard scrolling

Files: src/app/confirmation.rs

Action: In ConfirmationWindow::handle_event, before widget dispatch, add keyboard event handling for ArrowUp, ArrowDown, PageUp, and PageDown. These adjust the atomic scroll offset (clamped). PageUp/PageDown scroll by visible_lines - 1 lines. Arrow keys scroll by 1 line. Keyboard scrolling is handled before widget dispatch so it works regardless of which widget is focused.

// In handle_event, before widget dispatch, after CloseRequested and y/n/Escape:
WindowEvent::KeyboardInput {
    event: key_event, ..
} if key_event.state == ElementState::Pressed => {
    // ... existing y/n/Escape checks ...

    // Scroll keys (works regardless of focus)
    match &key_event.logical_key {
        Key::Named(NamedKey::ArrowUp) => {
            scroll_preview(&self.preview_scroll_offset, -1, max_scroll);
            // Don't return — let it also go through widget dispatch
            // (fall through to widget dispatch for focus traversal)
        }
        Key::Named(NamedKey::ArrowDown) => {
            scroll_preview(&self.preview_scroll_offset, 1, max_scroll);
        }
        Key::Named(NamedKey::PageUp) => {
            let lines = -(self.preview_visible_lines as isize - 1);
            scroll_preview(&self.preview_scroll_offset, lines, max_scroll);
        }
        Key::Named(NamedKey::PageDown) => {
            let lines = self.preview_visible_lines as isize - 1;
            scroll_preview(&self.preview_scroll_offset, lines, max_scroll);
        }
        _ => {}
    }
}

fn scroll_preview(offset: &AtomicUsize, delta: isize, max: usize) {
    let current = offset.load(Ordering::Relaxed) as isize;
    let new = (current + delta).clamp(0, max as isize);
    offset.store(new as usize, Ordering::Relaxed);
}
Outcome: ArrowUp/Down and PageUp/Down scroll the preview regardless of which widget is focused. Scroll is clamped to [0, max(0, total_lines - visible_lines)]. Wheel scrolling continues to work via PreviewPane's handle_event. All scrolling routes are covered.

5 Test Strategy

wrap_preview_text

Verify Text is split into lines, each line is escaped via safe_preview_line, and each escaped line is wrapped at max_chars. Control characters are visibly escaped. Raw text is not modified.
Mock None — pure function, no dependencies.
Variations
  • Empty string → empty Vec
  • Single short line ("hello") at max_chars=10 → ["hello"]
  • Single long line ("hello world") at max_chars=5 → ["hello", " worl", "d"]
  • Tab character → escaped to → (U+2192)
  • C0 control (0x01) → escaped to U+2401
  • \r character preserved in escaped output
  • Multi-line with \n and \r\n → each line wrapped independently
  • Empty lines between content → preserved as empty strings
  • max_chars=1 → every character on its own line (stress test for minimal width)

PreviewPane — intrinsic size

Verify Intrinsic size reflects widest line width and configured visible-line count. Empty lines produce zero width from text (but minimum from constraints).
Mock Setter for thread-local TextMetrics (already exists via set_current_metrics).
Variations
  • Empty Vec → width from constraints minimum, height = 0
  • Single 5-char line, visible_lines=10 → width=5*cell_width+pad, height=10*line_height
  • Mixed-width lines → width from widest
  • Tight constraints smaller than intrinsic → constrained size

PreviewPane — paint_primitives and scroll

Verify Only lines in [offset, offset+visible_lines) produce Text primitives. Offset 0 shows first N lines. Offset beyond total lines produces no primitives.
Mock Pre-populated wrapped lines Vec. Thread-local text run queue (existing mechanism).
Variations
  • 5 lines, visible_lines=3, offset=0 → 3 Text primitives
  • 5 lines, visible_lines=3, offset=2 → 3 Text primitives (lines 2,3,4)
  • 5 lines, visible_lines=3, offset=4 → 1 Text primitive (last line only)
  • 5 lines, visible_lines=3, offset=5 → 0 Text primitives
  • 0 lines → 0 Text primitives regardless of offset
  • Each primitive's origin.y increments by line_height

PreviewPane — wheel event handling

Verify Wheel scroll events adjust the atomic scroll offset. Down-scroll increases offset (up to max). Up-scroll decreases offset (down to 0). Non-scroll events return Ignored.
Mock Synthetic UiEvent::Pointer with PointerPhase::Scroll and scroll_delta. Pre-set AtomicUsize.
Variations
  • Scroll down by 1 → offset += 1
  • Scroll up by 1 → offset -= 1
  • Scroll up at offset=0 → stays at 0
  • Scroll down at max → stays at max
  • Large scroll delta (e.g., 100) → clamped to valid range
  • Pointer Move event → Ignored
  • Keyboard event → Ignored

ConfirmationWindow — keyboard scroll shortcuts

Verify ArrowUp/Down and PageUp/Down keys adjust scroll offset and do NOT return Confirmed or Cancelled. They pass through to widget dispatch for Tab handling.
Mock Synthetic WindowEvent::KeyboardInput events with arrow/page keys. Pre-set AtomicUsize for scroll offset.

  • ArrowUp at offset=0 → remains 0
  • PageDown with total_lines < visible_lines → remains 0
