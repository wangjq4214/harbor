Design Decisions

  • Draw provider as Box<dyn Fn(ExternalDrawId, Rect, &mut wgpu::RenderPass) + 'static> stored on Runtime. A function pointer stored once during App init avoids threading lifetime parameters through every encode() call. The 'static bound is acceptable because the App owns all terminal state through its own fields, and winit/wgpu references are already 'static.
  • Input deferral via in-Runtime queue, not a stored callback. External input events are queued per-ExternalDrawId during event routing and drained after the event walk. This avoids the App needing to supply a second callback — the App drains the queue alongside update(). Simpler API surface.
  • Encode batches all quads before the first External in one draw call, then invokes external providers. For T0002 the terminal is the root widget (no quads with higher paint_order), so all-quads-then-external is correct. When future overlay widgets are added, the interleaving infrastructure (paint-order iteration, range-based quad encode) already exists and just needs the split condition adjusted.
  • CustomPaint fills available space by default. The terminal should occupy the full viewport. Rather than requiring the App to specify a size, CustomPaint expands to fill its constraints, matching the behavior needed for the root widget.
  • No new type for the provider contract — a type alias suffices. A single-function callback has no internal state or multiple methods. Introducing a trait would be ceremony without benefit. If a second External consumer arrives, the signature can be promoted to a trait.

Step 3: Modify Runtime::encode() to handle External primitives

Files: crates/harbor-widget/src/runtime.rs

Action: Change encode() to: (a) iterate SceneGraph items in paint order via items(); (b) collect contiguous Quad items into one batch and call QuadRenderer::encode() for them; (c) for each External item, set a scissor rect on the RenderPass matching the item's layout rect (converted to physical pixels via viewport scale factor), invoke the stored external_draw callback with the draw ID and logical rect, then reset the scissor; (d) continue encoding remaining Quads after the last External.

// pseudo-code for encode()
fn encode(&mut self, queue, pass, viewport) {
    let items = self.scene_graph.items();
    let mut quad_start = None;
    for (i, item) in items.iter().enumerate() {
        match &item.primitive {
            Primitive::External { draw } => {
                // flush preceding quads
                if let Some(start) = quad_start {
                    self.renderer.encode_range(pass, start, i - start);
                    quad_start = None;
                }
                // apply clip and call external provider
                if let Some(ref cb) = self.external_draw {
                    let rect = self.scene_rect_for(item.id);
                    let phys = viewport.logical_to_physical(&rect);
                    pass.set_scissor_rect(phys.x, phys.y, phys.w, phys.h);
                    cb(*draw, rect, pass);
                    pass.set_scissor_rect(0, 0, viewport.physical_size.0, viewport.physical_size.1);
                }
            }
            Primitive::Quad { .. } => {
                if quad_start.is_none() { quad_start = Some(i); }
            }
            _ => {}
        }
    }
    // flush trailing quads
    if let Some(start) = quad_start {
        self.renderer.encode_range(pass, start, items.len() - start);
    }
}
Outcome: Widget quads and external terminal content are drawn in correct paint order within a single RenderPass. Scissor clipping restricts terminal output to the CustomPaint rect.

Step 4: Create CustomPaint widget

Files: crates/harbor-widget/src/widgets/custom_paint.rs (create), crates/harbor-widget/src/widgets/mod.rs

Action: Create CustomPaint struct with field draw_id: ExternalDrawId and children: Vec<View>. Implement Component (builder pattern: new(id) -> Self, child(widget)). Implement AnyView: is_focusable() → true; intrinsic_size() fills constraints.max; paint_primitives() returns vec![Primitive::External { draw: self.draw_id }]; handle_event() records input for deferred delivery (see Step 5); hit_test() uses default point-in-rect.

pub struct CustomPaint {
    pub draw_id: ExternalDrawId,
    children: Vec<View>,
}

impl AnyView for CustomPaint {
    fn is_focusable(&self) -> bool { true }
    fn paint_primitives(&self, _rect: Rect) -> Vec<Primitive> {
        vec![Primitive::External { draw: self.draw_id }]
    }
    fn handle_event(&self, event: &UiEvent, ctx: &mut EventCtx, _rect: Rect) -> EventHandled {
        // Queue for deferred delivery to App terminal handler
        crate::runtime::queue_external_input(self.draw_id, event.clone());
        EventHandled::Handled
    }
}
Outcome: A focusable widget that marks a region for external painting and routes input events to the deferred external-input queue.

Step 5: Add external input deferral to Runtime

Files: crates/harbor-widget/src/runtime.rs

Action: Add pending_external_input: Vec<(ExternalDrawId, UiEvent)> field to Runtime. Add queue_external_input(id, event) (pub(crate), called by CustomPaint::handle_event). Add drain_external_input() -> Vec<(ExternalDrawId, UiEvent)> public method. In dispatch(), drain the queue after event routing completes and return events alongside the FrameRequest.

// Key change in Runtime::dispatch():
pub fn dispatch(&mut self, event: UiEvent, now: Instant) -> (FrameRequest, Vec<(ExternalDrawId, UiEvent)>) {
    let needs_redraw = self.route_event(&event);
    if needs_redraw && let Some(root_id) = self.root_id {
        crate::signal::mark_dirty(root_id);
    }
    let external_events = std::mem::take(&mut self.pending_external_input);
    (FrameRequest { needs_redraw }, external_events)
}
Outcome: Terminal input events pass through Widget event routing (focus, hit-testing, capture/bubble) and are delivered to the App as a deferred batch after the event walk completes — the App then forwards them to the existing terminal input path.

Step 8: Wire terminal drawing through external draw callback

Since closures with 'static bound cannot capture &self, restructure: store the callback as a thin function pointer plus a *const () context, or split render_frame so the Runtime::encode call passes the external draw logic inline. This avoids 'static lifetime issues and lets the App borrow ui only during the encode call.

Step 9: Translate winit events to UiEvent and dispatch to widget Runtime

Files: src/app.rs

Action: In window_event(), for keyboard and pointer events, translate winit event types to harbor_widget::input::event::UiEvent variants and call self.widget_runtime.as_mut().unwrap().dispatch(event, now). Drain returned external input events and forward them to the existing terminal input path (PTY write) for the terminal's ExternalDrawId. Pointer events: translate MouseInput to Pointer(Down/Up/Move), CursorMoved to Pointer(Move), MouseWheel to Pointer(Wheel). Keyboard events: translate KeyInput to Keyboard(KeyDown/KeyUp). Focus events: translate Focused → Focus(Gained), unfocused → Focus(Lost).

Outcome: Winit keyboard and pointer events flow through the widget Runtime's capture→target→bubble routing. Only events reaching the focused CustomPaint node are dequeued as external input and forwarded to the terminal.

Step 10: Handle stale ExternalDrawId safely

Files: crates/harbor-widget/src/runtime.rs

Action: In encode(), when an External item's draw ID is not recognized by the external draw callback (the callback returns without drawing), the Runtime should not panic. Implement the guard by logging a warning and continuing. For input: if a deferred external input event has an ExternalDrawId with no matching living CustomPaint fiber, drop the event silently.

Outcome: Unknown or stale external IDs never cause a panic or draw unrelated content.

4 Edge Cases

#ConditionExpected BehaviorOwning Step
1 External draw callback is None when Runtime encounters an External primitive Runtime skips the external draw silently — no quad rendering, no panic. A warning is logged. Step 3
2 ExternalDrawId in deferred input queue has no matching CustomPaint fiber (fiber was unmounted between event routing and drain) Event is dropped silently. No panic or delivery to unrelated fiber. Step 5
3 CustomPaint rect is zero-sized (viewport not yet set, or window minimized) Scissor rect of zero area is set on the RenderPass — wgpu treats this as a no-op draw. No crash. Step 3
4 Multiple External primitives with different draw IDs in the same frame Each is invoked in paint order with its own rect and clip. Quads between them are flushed in correct order. Step 3
5 Widget tree has no External primitives (e.g., before CustomPaint is set as root) encode() behaves as before — all quads encoded in a single draw call. No external draw callback invoked. Step 3
6 Keyboard event arrives when CustomPaint is not focused (focus is on another widget, or no widget has focus) Event routes via capture→target→bubble. If no focused fiber or target is not CustomPaint, the event is not queued for external input — no terminal input is sent. This is correct: unfocused terminal should not receive keyboard input. Step 5, Step 9
7 Scale factor changes between viewport updates (DPI change while window is being dragged across monitors) Next set_viewport() call updates the scale factor; next encode() uses the current viewport's scale factor for scissor rect conversion. No stale scale factor persists beyond one frame. Step 6
