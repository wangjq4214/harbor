# Nonblocking Transactional Terminal Resize

**Spec ID:** 0046
**Status:** Draft
**Date:** 2026-10-27
**Sources:** User refinement confirming six constraints: asynchronous ACK acquisition without UI blocking or long-held Terminal locks; exactly-once old/new-geometry ordering; latest-target request merging; reader release and explicit incomplete recovery; multi-terminal font-reload atomicity; unified normal-drain/ACK dispatch. The user selected a Spec-only endpoint.
**Decision:** [ADR 0095](../adr/0095-event-driven-resize-barrier-and-shared-reader-dispatch.md).
**Regression contracts:** [0014 — content-preserving resize](./0014-content-preserving-resize-reflow.md), [0023 — atomic configuration reload](./0023-atomic-manual-configuration-reload.md). This specification changes how barrier acquisition progresses, not their content-retention or accepted-configuration policies.

## Requirements

### R1 — Nonblocking acquisition and available Terminal access

Ordinary window-driven resize and configuration/font-driven resize must not synchronously wait for a reader ACK on the UI thread. A pending ACK must not retain a Terminal lock across the wait, including when acquisition is moved to another thread. The application must continue processing UI events and permit other legitimate Terminal access while acknowledgement is withheld.

Waiting for ACK is distinct from committing geometry: a pending request is not a completed resize, and unacknowledged geometry must not become authoritative. Already committed geometry remains authoritative while acquisition is pending. This does not freeze normal PTY output or roll back ordinary output mutations.

**Verification:** Hold an ACK behind a controllable gate. Before releasing it, process an unrelated UI action, access the same Terminal through its normal synchronization boundary, and observe the old committed dimensions. These observations must not depend on releasing the gate or reaching the barrier timeout.

### R2 — Exactly-once stream ordering across geometry changes

Retain the epoch-qualified acknowledged reader barrier from [ADR 0043](../adr/0043-acknowledged-pty-resize-barrier.md). The reader publishes every completed pre-ACK read exactly once before its matching ACK and starts no further read while paused. Parse all preceding byte events under the old geometry before preparing the committed resize. On success, commit the new geometry before resuming and interpreting following bytes under it.

A request racing with completion/publication of a read must not drop, duplicate or reorder bytes. Preserve parser state across the boundary, including incomplete escape sequences and ordinary protocol replies. An obsolete ACK must not complete a newer epoch or cause an unacknowledged resize.

The post-ACK/new-geometry rule applies to successful resize. If acquisition or preparation fails before PTY change, retain old geometry and continue the stream against it after reader release. If PTY effects require compensation or reconciliation, apply R5 rather than falsely assume either a successful new-size commit or complete restoration.

The boundary orders reader-observed chunks, not when the child generated bytes still unread in an OS pipe.

### R3 — One ordered event-dispatch contract for drain and resize

Ordinary PTY drain and pending resize coordination must share reader-event dispatch. No drain entry point may silently consume an ACK needed by resize, independently race the resize path for events, or parse post-boundary bytes against an uncommitted geometry. Byte events are parsed exactly once; ACKs are delivered to the matching pending coordination state or recognized as obsolete without satisfying another request.

This guarantee applies when drain is entered from output-ready handling, frame preparation/scheduling or input handling. An ACK-only wake must advance a pending resize even when no text changes. Pending acquisition, its deadline and reader release must not depend on receiving additional output or on an ordinary terminal frame being presented. Preserve bounded ordinary drain work and continuation/wake behavior rather than replace the current per-turn budget with an unbounded queue drain.

**Verification:** Arrange ordinary drain to receive the matching ACK before any separate resize-progress call; resize must still advance exactly once. Repeat with no byte events following the ACK and with ordinary presentation suppressed. A stale ACK must not consume the new request's opportunity to complete or resume it incorrectly.

### R4 — Latest-target request merging

Continuous resize requests retain only the latest pending target dimensions instead of a FIFO of every intermediate size. While ACK acquisition is held pending, replace superseded targets without preparing/reflowing buffers or resizing the native PTY for each discarded target. Once acquisition can complete, the applicable expensive resize work uses the latest target.

Request merging must preserve R2/R3 ordering and epoch safety and must not bypass the existing PTY/model commit and compensation rules. Distinguish the committed geometry from the pending target; the latest request is not evidence that a native effect or model commit succeeded. Existing row/column normalization and unchanged-size behavior remain applicable.

**Verification:** Withhold acknowledgement, submit several distinct sizes, then release it. The terminal/PTY geometry must finish at the normalized last target; superseded targets must not each trigger detached preparation/reflow and native resize. Repeat bursts and target changes around progress boundaries, including a target returning to the current size, without stream loss or stale completion.

### R5 — Bounded failure, reader release and explicit fault recovery

Acquisition remains bounded. Timeout, interruption failure, session closure, preparation failure, PTY resize failure and transaction abandonment must not strand a reader paused for an obsolete request. Release/resume the live reader on every completion path; closure must permit teardown rather than require restarting a closed reader or session. Late acknowledgements after timeout or cancellation cannot commit discarded work or satisfy another epoch.

Retain detached preparation and the allocation-free, infallible model commit following successful PTY resize. Before the native commit point, failures leave authoritative PTY/model geometry unchanged, apart from normal old-geometry output processing. Where earlier native effects require rollback, attempt the existing compensation. If full rollback cannot be achieved, explicitly enter/report fault recovery rather than ordinary success, an allegedly restored geometry, or a partially accepted configuration.

For configuration compensation failure, retain the previous accepted settings/resources, resume readers, attempt model/render/input geometry reconciliation to the last successfully established PTY geometry under the accepted font policy, and identify failed operations and unrecovered sessions, as required by [ADR 0061](../adr/0061-manual-reload-compensation-failure.md). Fault recovery is distinguishable from pending, committed and ordinarily rejected outcomes; this contract does not prescribe a public enum or a new recovery-exit policy.

**Verification:** Inject each failure separately, then deliver a late ACK and attempt a subsequent valid resize where the session remains live. Verify reader release, no stale commit, honest geometry and pending damage, and successful ordinary retry when rollback succeeded. Inject failed compensation separately and verify explicit recovery status and unchanged accepted configuration rather than assert restoration.

### R6 — Application-coordinated, multi-terminal font reload

Font reload remains one coordinated configuration transaction across all applicable terminals, including inactive and alternate-screen sessions, and the future-resource factory. Individual ACK arrival or completion of one session's preparation/native resize must not publish a candidate font, metrics, resources or accepted settings to only part of the application.

Apply R1 to every session while the group is acquiring ACKs: one slow reader must not make the UI wait or leave Terminal locks held across acquisition. Preserve [spec 0023](./0023-atomic-manual-configuration-reload.md)'s validation, resource ownership and group commit boundary. Publish a coherent accepted generation only after required preparation and native effects succeed for the group. On rejection, retain previous accepted configuration; compensate earlier successful PTY effects on later-session failure. A compensation failure follows R5/ADR 0061 and does not authorize partial configuration acceptance.

Ordinary resize progress and pending font-driven geometry must respect the same reader-event ownership and transaction ordering. Their interleaving cannot let a normal drain steal a group ACK or let a standalone resize silently publish part of a font candidate.

### R7 — Preserve established terminal behavior

Asynchronous acquisition changes neither session/PTY/child identity nor buffer-specific resize semantics. Preserve normal bounded primary/history retention, ConPTY live-primary policy, rectangular alternate resize, saved-primary handling, cursor/selection/review/anchor validity, parser continuity and pending damage under spec 0014 and [ADR 0060](../adr/0060-font-reload-uses-normal-bounded-resize.md).

Font reload remains terminal-only and must not reset sessions, clear buffers, change independent UI fonts or reject ordinary history eviction/clipping as a new lossless-retention policy. Configuration atomicity is not a promise to freeze or undo child execution/output during asynchronous acquisition.

## Solution

Use the established event-driven acknowledged barrier direction in ADR 0095. Treat request submission, ordered ACK dispatch, transaction completion and failure/recovery as distinguishable progress, not one synchronous UI call that waits for the reader. Keep pending target and epoch coordination available without retaining a borrowed/locked Terminal across the ACK wait.

Shared dispatch preserves a single interpretation of the reader stream for normal drain and resize. After the matching boundary and all pre-ACK bytes have been processed, existing detached preparation, PTY effect and model commit guarantees continue to apply. Request merging limits superseded work; application-level coordination remains responsible for coherent font/configuration acceptance across terminals.

This describes responsibilities and exchanged guarantees, not an implementation plan, prescribed module layout, async runtime, thread design or public API signature.

### Current integration surfaces

These are verified entry points, not required future names or file layout:

- `crates/harbor-terminal/src/io.rs`: `TerminalSession::acquire_resize_barrier`, reader commands/events, `TerminalIo::drain`, parser/reply delivery and reader lifecycle. The current two-second `recv_timeout` loop and no-op `BarrierAck` drain arm are the behaviors to replace.
- `crates/harbor-terminal/src/lib.rs`: ordinary resize, render preparation, drain and frame-demand paths that can acquire or consume reader events.
- `crates/harbor-terminal/src/configuration.rs`: configuration geometry preparation, group native effects, compensation and reader release.
- `src/tab_coordinator.rs`: application-owned configuration acceptance, Terminal synchronization, font/render resources and future-session factory.
- `harbor-pty` control capabilities: interrupting blocked reads, native resize and session teardown without exposing raw platform handles.

## Decisions and Traceability

- **Nonblocking wait without long-held Terminal locks:** User constraint 1 and ADR 0095; moving a blocking wait behind a retained lock is insufficient.
- **Keep ordered barrier, not opportunistic drain:** User constraint 2, ADR 0043 and ADR 0095; removing the barrier loses the proven reader boundary.
- **Unified ACK dispatch:** User's additional drain finding and ADR 0095; the current no-op ACK arm cannot remain for pending acquisition.
- **Latest-target coalescing:** User constraint 3 and ADR 0095; avoid expensive intermediate work without weakening transaction safety.
- **Explicit incomplete recovery:** User constraint 4 and ADR 0061; native compensation is fallible and restoration cannot be assumed.
- **One configuration generation:** User constraint 5, [ADR 0059](../adr/0059-atomic-manual-reload-and-terminal-only-fonts.md) and spec 0023; individual asynchronous success is not group acceptance.

## Verification Guidance and Limits

Use controlled reader gates and clocks to establish progress and race ordering, rather than sleeps or an invented latency threshold. Observe UI event completion, acquisition of the actual Terminal synchronization boundary, committed geometry, per-target preparation/native-effect counts, byte interpretation, epoch delivery, reader release, accepted resource generations and recovery outcomes.

Exercise budget-exhausted drains and ACK-only wakes, read completion before publication, blocked-read interruption, timeout racing with ACK, repeated targets/epochs, session teardown, and multi-session success/rejection/compensation failure. Validate actual Windows ConPTY interruption and repeated resize/font-reload behavior with cmd/PowerShell pending input, inactive tabs and a persistent alternate-screen application; deterministic reader tests alone do not prove platform behavior. Retain spec 0014/0023 regression evidence obligations.

Record revision/dirty scope, Windows/ConPTY/application versions, exact steps, expected versus observed results and PASS/FAIL/NOT RUN/BLOCKED. This specification is requirements work only: no implementation, tests or Windows runtime acceptance is claimed.

No new timeout value, quantitative lock/latency budget, public API shape or recovery-exit mechanism is selected here. Bounded acquisition, observable progress before ACK release and the explicit recovery/atomicity guarantees are binding regardless of those implementation details. There are no additional assumed domain behaviors.

## Out of Scope

- Implementation planning, ticket decomposition, code changes or QA execution at this Spec-only endpoint.
- Replacing established buffer-specific retention/reflow, ConPTY geometry or configuration publication policy.
- Claiming generation-time ordering for unread OS-pipe bytes, freezing child execution, restarting sessions or introducing hidden lossless content backups.
- Selecting a new timeout, async runtime, public API or new recovery-exit policy merely to express asynchronous ACK progress.
